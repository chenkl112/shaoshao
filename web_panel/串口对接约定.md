# 给底盘负责人的串口对接约定

本次采用 `serial_jsonl_v1`。你负责上位机导航、网页、速度门控和串口收发；底盘负责人实现下位机四轮控制、yaw 闭环、编码器采样和本机超时停车。下位机不用运行 ROS，也不用实现建图或导航。

## 通信约定

| 项目 | 约定 |
| --- | --- |
| 数据 | UTF-8 JSON，一帧一行，每帧以 LF 字节 `0x0A`，即 `\n` 结束 |
| 串口 | 8 数据位、无校验、1 停止位，无软/硬件流控 |
| 波特率 | 建议 460800；双方确认芯片和适配器支持后填写，实际值仍待确认 |
| 频率 | 上位机命令 50 Hz；下位机实际状态建议 50 Hz |
| 坐标 | x 向前，y 向左，z 向上；俯视逆时针转向为正 |
| 单位 | vx、vy 为 m/s；wz、yaw 角速度为 rad/s；yaw 角为 rad |
| 帧长度 | 每行最多 4096 字节，使用紧凑 JSON；实际状态尽量保持短小 |
| 超时 | 约 0.3 s 没有合法新命令，下位机将底盘目标归零 |

连接 USB 串口或电平匹配的 UART；UART 交叉连接 TX/RX 并共地。双方先确认 TTL/RS232/RS485 类型与电压，不能将不同物理电平接口直接相接。

## 上位机发给下位机

数值仅展示格式，每行末尾还需要一个真实换行字节：

```json
{"type":"command","version":1,"seq":27,"vx":0.1,"vy":-0.05,"wz":0.2,"yaw_target_encoder_rad":1.2}
```

| 字段 | 下位机如何处理 |
| --- | --- |
| type / version | 必须为 command / 1，不支持的版本拒绝执行 |
| seq | 上位机进程内递增命令编号；上位机重启会重新计数，下位机应允许重新建立通信 |
| vx / vy / wz | 车体速度目标，由下位机完成麦轮逆解和轮速闭环，不能把 m/s 当成电机 RPM |
| yaw_target_encoder_rad | 原始 yaw 编码器坐标中的目标角，由下位机完成位置闭环 |

`vx=vy=wz=0` 表示底盘停止，yaw 仍保持给定角度。网页待机、切换模式或门控关闭时都发零底盘速度，因此协议无需另传建图/导航/待机模式。导航起始上限为平面合速度 0.3 m/s、转速 0.5 rad/s；下位机也按实际能力限幅。

## 下位机回给上位机

**必须回传实际 yaw 状态**，仅接收速度、不回反馈无法完成 yaw 到位判断和雷达 TF：

```json
{"type":"state","version":1,"seq":51,"yaw_encoder_rad":1.2,"yaw_rate_rad_s":0.0}
```

角度和角速度均在原始编码器坐标中，必须来自真实采样，不能直接回传目标值。反馈 `seq` 随新采样严格递增；重复序号不能刷新上位机超时。下位机重启后重新启动串口桥，避免序号归零被误判为旧帧。桥兼容省略 version 的旧版 state，新实现统一发送 version=1。

轮式里程计可选，上位机定位主来源为 MID360 + FAST-LIO。已有里程计可一起回传：

```json
{"type":"state","version":1,"seq":52,"yaw_encoder_rad":1.2,"yaw_rate_rad_s":0.0,"odom":{"x":0.0,"y":0.0,"yaw":0.0,"vx":0.1,"vy":-0.05,"wz":0.2}}
```

odom 的 x/y/yaw 为轮式局部坐标位置和朝向，vx/vy/wz 为车体坐标实际速度。提供时必须给齐六个字段，否则省略整个 odom 字段。所有数值必须有限，不能包含 NaN/Infinity。

双方确认以下编码器换算：

```text
关节角 = sign × (原始编码器角 - zero)
原始目标角 = 关节目标角 / sign + zero
```

sign 取 +1 或 -1，zero 为关节零位对应的原始读数。若下位机输出已经是标定后的 ROS 关节角，可约定 sign=+1、zero=0；确认前不要擅自填写。yaw 保持目标须在机械限位内。轮径、轮距、轴距、减速比和四轮 PID 由底盘负责人配置，不需要放入上位机串口报文。

## 分工和联调

| 你负责的上位机 | 底盘负责人负责的下位机 |
| --- | --- |
| MID360、TF、建图、定位、Nav2、网页 | 四轮速度闭环、yaw 闭环、限位、独立急停 |
| 按 50 Hz 发目标，接收并转换实际反馈 | 逐行校验报文，连续采样编码器并回传状态 |
| 反馈断流时发零底盘速度 | 通信中断或上位机掉电时自行超时停车 |

先在底盘负责人确认的测试条件下检查零速度报文与 yaw 反馈，再确认前进、左移、逆时针方向，最后接入网页三个模式。上位机发送零速度与车辆实际停稳分别检查。

你可以先单独运行串口桥，无需填写雷达安装几何：

```bash
cp web_panel/serial.example.yaml web_panel/serial.yaml
# 填写串口、波特率、yaw 目标与编码器换算
python3 web_panel/chassis_bridge.py --config web_panel/serial.yaml --check-config
source /opt/ros/humble/setup.bash
python3 web_panel/chassis_bridge.py --config web_panel/serial.yaml
```

新终端 source ROS 后查看 `/yaw/joint_states`，若提供轮式里程计再查看 `/wheel/odom`。独立桥只转换串口和 ROS 话题，没有网页模式门控；不要同时运行第二个桥。接入完整系统时停止独立桥，改由 `bringup.py` 启动串口驱动。完整系统仍需车体外轮廓和雷达安装几何，用于碰撞检查和 TF。

详细编码器与 ROS 约定见 [硬件接口](硬件接口.md)，上车命令见 [中文部署指南](README.md)。
