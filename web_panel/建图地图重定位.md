# 使用建图地图进行搬车后全局重定位

MID360 优先使用三维建图点云找回位置；二维栅格继续用于 AMCL 确认、规划与完整车体碰撞检查。
三维结构有助于区分二维投影相似的走廊，但完全重复的场景仍可能无法唯一定位。

## 地图选择与来源

导航始终使用当前所选地图目录的 `site.yaml`、其引用的图像、`site.pcd` 与 `keyframes/`。
生成参数 `navigation_runtime/frames.yaml` 记录绝对地图路径、定位后端和光学中心/IMU 外参。

- 有 PCD 和完整索引：20 环 × 60 扇区的 ScanContext 描述检索候选，再用 small_gicp 对齐保存的 PCD。
- 有 PCD、从未建立关键帧目录的旧图：二维全地图搜索提供候选，再由三维配准验证。
- 仅有二维地图：保留全平面位置、360° 朝向搜索，不假称使用了 PCD。
- 已有索引但未完成、损坏或与 PCD SHA256 不符：保持停车并报错，不能静默切换定位来源。

HWSentryNav26 原版的 `odom_localizer` 使用先验 PCD 和 small_gicp 持续校正里程计，包含误差、重叠率、信息矩阵与平滑检查。
其初值来自预设蓝/红方位置、默认位置或当前校正，本身没有任意地点的候选检索。
本机 `shaoshao-hw` 增加了关键帧全局检索；当前工程借鉴其索引格式与检索逻辑，并保留 AMCL 独占地图 TF。
没有同时启动 HW 定位器和 AMCL 发布同一条 `map → navcar_odom`。

## 停车、搜索、确认与续行

1. 独立扫描不匹配、里程计重置/跳变或全图核对发现位置不一致时，撤销运动许可，保留原目标。
2. 独立进程读取保存地图并搜索当前扫描的全局位置和朝向。查询不接收最后位置、导航目标或仿真真值。
3. 三维配准要求：至少 1000 个原始点、500 个降采样点、80% 重叠率、全局搜索归一化误差 ≤ 0.05、信息矩阵最小特征值 ≥ 1000、条件数 ≤ 1e6。全局误差门槛比 HW 已知位置附近纠偏的 0.30 更严格；保留 40 个描述候选、至多 12 个不同地点供配准与歧义检查。综合重叠率、配准误差和保存二维地图的端点/空闲射线一致性比较候选：分数至少 0.80、与不同地点相差至少 0.07。多个相近可信地点仍判为歧义。
4. 两次独立新观测的候选一致后，向 AMCL 提供初值。AMCL 的位置、朝向、协方差、新鲜度及独立二维扫描继续验证；至少三个扫描和一秒稳定后才确认。
5. 清除旧变换下积累的全局和局部障碍，等待两幅新鲜代价图以及完整车体区域有效，再重规划原目标。

正常跟踪的小步校正限制不会拒绝已经全局确认的新位置。取消、手动接管和地图切换会撤销旧任务和迟到结果。
搜索期间不输出盲目旋转或平移；点云不足、结构重复、地图损坏或配准质量不足时继续停车等待。
无额外轮廓余量、真实车体半径和原有 180/300/500 ms 输出/里程计/局部地图门槛均保留。

## 新建图与部署

安装和更新步骤见 [部署说明](../deployment/README.md)。增加 `small-gicp==1.0.1` Python 绑定，计算在独立进程中完成。
建图记录器每移动 0.25 m 或转动 10° 保存传感器局部关键帧。
停止时先保存静态 PCD，再剔除关键帧中距静态地图超过 0.1 m 的点，保存完整索引和 PCD SHA256。
保存失败会说明点云已保存但索引未完成，并保留建图运行状态以便重试；不能把未完成索引当成导航地图。

2026-10-24 上传数据的离线检查发现多组静态点云很稀疏；7 组可评估地图的 21 个留出帧查询均未通过质量门槛，
另有 4 组地图/点云不可用，1 组仅一帧不能做独立留出验证。此结果意味着这些原始文件不能作为已通过的三维重定位验收地图。
不能靠修改 YAML 分辨率、填白未知区或降低重叠门槛修复。需要重新采集足够静态结构，并检查二维投影包含连续的真实空闲观测。

## 复现验证

```bash
python3 -m unittest discover -s web_panel -p 'test*.py' -q
SHAOSHAO_ROS_ENV=/path/to/ros_env.sh python3 validation/sentry_sim/run_relocalization_suite.py --output /tmp/relocalization
SHAOSHAO_ROS_ENV=/path/to/ros_env.sh bash validation/sentry_sim/run.sh \
  --case kidnap --pointcloud-localization --odom-mode blind \
  --relocate-to 4 -3 -1.1 --repeat-kidnap -3.8 -3.1 1.57 --timeout 150 --output /tmp/pcd-kidnap
python3 validation/sentry_sim/check_saved_clouds.py --maps-root /path/to/uploaded/maps --output /tmp/saved-map-check.json
ROS_DOMAIN_ID=189 ROS_LOCALHOST_ONLY=1 python3 validation/sentry_sim/check_index_recorder.py --output /tmp/index-recorder
```

Gazebo 用例使用 sentry_planning 房间碰撞几何、实际搬移仿真刚体、解析扫描和模拟局部里程计。
PCD 仿真地图和关键帧在搬车前生成；搬车真值只给 Gazebo 和结果评估，不注入 AMCL 或检索器。
这是算法与 ROS 集成验证，不是 MID360/FAST-LIO 闭环或实车验收。
