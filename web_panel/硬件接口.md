# 底盘和 yaw 下位机接口

本文件定义双方已选的 **serial_jsonl_v1 串口协议**。你负责上位机串口收发，底盘负责人实现下位机的四轮闭环、yaw 闭环和反馈。可直接交给对方的简版见 [串口对接约定](串口对接约定.md)。控制板型号、物理电平、串口和波特率仍待确认；以后改用已有厂商驱动时也可按 ROS 接口适配。

## 1. 坐标和闭环位置

vx 为车体向前、vy 为向左，单位 m/s；wz 为俯视逆时针旋转，单位 rad/s。四轮电机各自执行速度闭环；yaw 使用位置环及速度/电流内环，具体周期、PID 与限流由电机和控制板实测确定。ROS 只给目标，不承担电机级实时闭环。

当前普通控制和导航默认 `wz=0`，仅进行平移。Web 的“小陀螺”开关默认关闭，仅手动/建图模式显式开启后给定底盘 `wz`，起始 +0.5 rad/s。云台 yaw 关节目标始终保持固定，使用原串口字段，无需新增报文模式字段。

本版 yaw 目标为**相对底盘的关节角**。`/yaw/joint_states.position` 是零位、正方向标定后的真实关节角，而不是世界方位或未经处理的电机编码器计数；velocity 是关节角速度，rad/s。正方向绕 base_link 的 +z，逆时针为正。

ROS 反馈消息示意（数值仅为报文格式示例）：

```yaml
# sensor_msgs/msg/JointState，话题 /yaw/joint_states
header:
  stamp: <有效 ROS 时间，反馈采样时间或经确认的低延迟接收时间>
name: [yaw_joint]
position: [0.0]
velocity: [0.0]
```

## 2. 参考 JSONL 串口协议

UTF-8 JSON，每帧一行，以 `\n` 结束；不使用 Python repr，不使用逗号分隔的裸字符串。当前桥接按 50 Hz 发送命令并读取状态。实际波特率必须与 MCU 一致。

上位机到 MCU：

```json
{"type":"command","version":1,"seq":27,"vx":0.1,"vy":0.0,"wz":0.0,"yaw_target_encoder_rad":1.2}
```

| 字段 | 含义 |
| --- | --- |
| `seq` | 本次桥接进程递增命令序号，用于诊断；MCU 必须允许上位机重启后建立新会话 |
| `vx/vy/wz` | 车体速度目标，已通过模式门控；MCU 还需按自身能力限幅 |
| `yaw_target_encoder_rad` | 已转换到原始 yaw 编码器坐标的目标，rad |

编码器转换定义：

```text
关节角 = encoder_sign × (原始编码器角 - encoder_zero)
原始目标角 = 关节目标角 / encoder_sign + encoder_zero
```

`encoder_sign` 只能取 +1 或 -1。原始编码器角的多圈展开/零位必须稳定；如果传感器回绕，先在下位机正确展开。机械限位与线缆绕转约束由下位机执行，不能仅依赖上位机角度门控。

MCU 到上位机，至少包含 yaw：

```json
{"type":"state","version":1,"seq":51,"yaw_encoder_rad":1.2,"yaw_rate_rad_s":0.0}
```

可选同时回传轮式里程计：

```json
{"type":"state","version":1,"seq":52,"yaw_encoder_rad":1.2,"yaw_rate_rad_s":0.0,"odom":{"x":0.0,"y":0.0,"yaw":0.0,"vx":0.0,"vy":0.0,"wz":0.0}}
```

`seq` 必须随新反馈样本严格递增，防止重复状态帧伪装为新反馈；下位机重启后需要重新启动桥接进程，或后续增加明确的 boot/session 标识。odom 的 x/y/yaw 为轮式局部原点下的位置，vx/vy/wz 为车体坐标中的真实反馈速度。串口桥将其发布到 `/wheel/odom`，不会发布定位 TF。

状态值必须为有限数，不能含 NaN/Infinity。每行不超过 4096 字节，状态不能省略 yaw 角速度。建议约 50 Hz 连续上报；串口桥以接收 ROS 时间为消息时间戳，需实测串口与固件队列延迟。若延迟不可忽略，应扩展设备采样时间与主机对时，不能只给延迟数据重新盖当前时间。

## 3. 下位机必须独立实现的逻辑

1. 上电时底盘零速，yaw 在确认编码器与限位后按合法目标保持；电机驱动错误时不继续执行旧速度。
2. 串口命令解析完整、字段合法才更新目标，丢帧或半帧不能组成错误命令。
3. 超过约 0.3 秒没有有效新命令，底盘目标归零。yaw 失联后保持、限流或失能策略按机械结构确定并实测。
4. 四轮速度闭环、yaw 位置/速度/电流闭环、机械限位和独立急停。
5. 反馈使用真实编码器与速度估计，不能把上位机目标值原样当反馈发送。

逻辑示意：

```text
通信任务：合法命令 -> 更新时间 -> 底盘 vx/vy/wz、yaw 目标
控制任务：超时检测 -> 底盘零速；麦轮逆解 -> 四轮速度环 -> 电机输出
          yaw 位置误差 -> 速度目标 -> 速度/电流环 -> yaw 电机输出
反馈任务：新编码器采样 -> 角度/速度/里程计 -> seq 递增 -> state JSONL
```

## 4. 常见 X 型麦轮逆解参考

仅适用于与下面符号一致的常见 X 型装配。前左/前右/后左/后右为 FL/FR/RL/RR，轮正方向统一为驱动车辆向前；r 为有效轮半径，a、b 分别为前后轮中心距与左右轮中心距的一半。角速度单位 rad/s：

```text
k = a + b
wFL = (vx - vy - k*wz) / r
wFR = (vx + vy + k*wz) / r
wRL = (vx + vy - k*wz) / r
wRR = (vx - vy + k*wz) / r

vx = r/4 * (wFL + wFR + wRL + wRR)
vy = r/4 * (-wFL + wFR + wRL - wRR)
wz = r/(4*k) * (-wFL + wFR - wRL + wRR)
```

轮子滚子装配、轴向、电机接线或编码器方向改变时，符号需要调整。减速比和编码器 tick 到角速度的换算属于底盘驱动；这些参数目前全部待测。首先分别验证前进、左移、逆时针旋转，不要用调 Nav2 参数补偿底盘坐标方向错误。

## 5. 收到硬件信息后需要补完的内容

- 控制板型号、现有固件、串口/CAN/Ethernet 协议与实际命令频率。
- yaw 电机型号、驱动模式、编码器零位/正方向/回绕、多圈及机械限位。
- yaw 参考系到底是相对底盘锁角还是世界锁定。
- 轮径、半轴距/半轮距、减速比、编码器分辨率、四轮电机方向。
- 底盘加减速能力、超时停车和急停的实际验证结果。

前两项及实际串口连接由双方对接，轮组和电机参数由底盘负责人维护，不是上位机导航配置的必填项。双方已选 JSONL 协议，待对方固件实现后按同一报文联调。
